# Architecture

This page describes only what exists in the code **today** (S08-R1). S03 added the domain tables, the functions that write and read them, and the releases seed. S04-R1 added the indexing path: `make ingest` stores versions and chunks for the S04 scope, and `make embed` stores one vector per distinct chunk text. S04-R2 added the answer path: `orgknow ask` embeds the question, finds the nearest chunk texts with an HNSW index, asks Claude for a structured answer that cites chunk ids, rejects any citation that wasn't retrieved, and prints the answer as JSON, with one Langfuse trace per ask. S05-R1 widened `make ingest` to the `full` scope: the docs pages of 3 SIGs, the website release records and the feature gates at every release 1.20 → 1.37, with a moved page or renamed gate kept as one document (later URLs and names become aliases), and `make reset-corpus` to rebuild from empty. S05-R2 added the date-scoped sources and the CHANGELOGs: every KEP in the 3 SIG folders and the governance docs, read at each release date plus `head`, each version dated by when its change was merged (a governance doc that moves stays one document); the blog posts dated from 1.20, one version per content change, starting at publication; and the 18 CHANGELOGs at the kubernetes lock head, chunked without their table of contents and download tables. S05-R3 made the chunk text final (no `{#id}` anchors or HTML comment blocks, HTML tables whole, oversize lists and pipe tables cut between items or rows, no download tables in any source), ended `make ingest` with a report whose fingerprint shows two ingests stored identical data, added `make ingest-report`, and embedded every distinct chunk text. S06-R1 added the eval harness: a golden-set loader with a label check against the database, retrieval metrics and answer checks AC1–AC3, and `make eval`, which runs every golden question through retrieval and one answer call, writes a results folder and rebuilds the ablation table. S07-R1 added lexical search (a `tsvector` column on `chunks`, generated by the database, with a GIN index; every content word of the question must match, ranked by `ts_rank_cd`), Reciprocal Rank Fusion (RRF), and `RETRIEVAL_MODE`: `dense` retrieves as before, `hybrid` fuses the 20 nearest texts and the 20 best full-text matches and keeps the best 10. Hybrid is the default since it passed the improvement rule (`docs/evaluation.md`). Every dense search sets its HNSW search width (`HNSW_EF_SEARCH`, 100). `make eval-retrieval` scores retrieval alone from the stored question vectors, with no paid call. S08-R1 added `RETRIEVAL_MODE=rerank` (ADR-008): hybrid's whole fused pool (about 21 texts) is scored by a local cross-encoder, `BAAI/bge-reranker-base` at a pinned revision on CPU-only PyTorch, and the best 10 by that score are kept; the model loads once per command, and only in that mode. There is no authority scoring yet. It is updated as slices land. The planned pipeline (ingestion → retrieval → generation → eval) is described in `CLAUDE.md` and `docs/product-spec.md`.

## Overview

```
  environment variables / .env
               │
               ▼
      Settings (settings.py)
        │                 │                         │
        ▼                 ▼                         ▼
  FastAPI app         make seed                 Alembic (db/migrations/env.py)
  (api/app.py)        (ingestion/seed.py)         │  URL gets the +psycopg driver name (db/url.py)
  /health  /ready       │  load_releases            │  SQLAlchemy engine → psycopg
        │               │  (ingestion/manifest.py)  │  0001: vector extension
  is_reachable          │  ◄── config/corpus_manifest.yaml
  (db/health.py)        │  upsert_releases          │  0002: domain tables + rules
  psycopg               │  (db/releases.py)         │  0003: embeddings keyed by chunk text
        │               │  psycopg                  │  0004: HNSW index on embeddings
        │               │                           │  0005: chunks.search_vector + GIN index
        ▼               ▼                           ▼
   Postgres 18 + pgvector 0.8.1 + btree_gist
   (Docker Compose, localhost:5433; dev DB `orgknow`, test DB `orgknow_test`)
        ▲
        │  psycopg, hand-written SQL (ADR-005)
  data-access functions (db/documents.py, db/versions.py, db/chunks.py, db/report.py)
        ▲                                   ▲
        │                                   │
  make ingest (ingestion/ingest.py)     make embed (embeddings/embed.py)
  manifest scope + lock → git_reader    chunk texts with no vector → batches
  → renames (chains, aliases)           → VoyageEmbedder (urllib) → Voyage API
  → normalize/hash → history, blog      → one vector per (content_hash, model)
  → plan_changes → versions
  → chunker → chunks
  → report (counts, skips, fingerprint)
  ◄── partial clones (CORPUS_CACHE_DIR)
```

The answer path, `orgknow ask "<question>"` (`cli.py`):

```
  question
     │
     ▼
  retrieve (retrieval/retrieve.py) ── VoyageEmbedder, input_type "query" ──► Voyage API
     │  RETRIEVAL_MODE=dense: search (db/retrieval.py), the RETRIEVAL_TOP_K (10) nearest texts
     │  by cosine distance, through the HNSW index at width HNSW_EF_SEARCH (100)
     │  RETRIEVAL_MODE=hybrid: RETRIEVAL_CANDIDATES (20) texts from each of search and
     │  search_lexical (every question word, by full-text rank); fuse (retrieval/fusion.py):
     │  RRF over the two lists (k = RRF_K, 60), the RETRIEVAL_TOP_K best
     │  RETRIEVAL_MODE=rerank: hybrid's whole fused pool (no top-K cut) → CrossEncoderReranker
     │  (retrieval/cross_encoder.py, loaded once by main) scores each (question, text) pair →
     │  rerank (retrieval/rerank.py): the RETRIEVAL_TOP_K best by score, ties in fused order
     │  every mode: each text once, with every release window it was valid in
     ▼
  answer (generation/generator.py) ── AnthropicGenerator, messages.parse ──► Anthropic API
     │  prompt (generation/prompt.py): one evidence block per hit
     │  validate (generation/validate.py): reject any cited id that wasn't retrieved;
     │  fill each citation in from its hit (title, section, windows, GitHub URL)
     ▼
  answer JSON on stdout; "tracing off" and errors on stderr

  Langfuse (only in cli.py, only with both keys): one trace per ask, named `ask`,
  with retrieve, generate and validate under it; flushed before the command exits
```

The eval path, `make eval` / `make eval-smoke` (`python -m orgknow.eval run`, `eval/runner.py`):

```
  golden file (EVAL_GOLDEN_PATH) ── load_golden_file (eval/golden.py): validate, ADR-007
     │  check_labels (eval/golden.py, SQL in db/eval.py): resolve aliases, count each
     │  label's texts; any 0 stops the run
     ▼
  question vectors (EVAL_VECTORS_DIR/<model>.json) ── only missing ones ──► Voyage API, 1 request
     │
     ▼  per question, in file order
  retrieve with the stored vector ─► answer ─► score_retrieval (eval/metrics.py)
                                              check_answer (eval/checks.py)
     │  an ask error becomes the row's `error`; no Langfuse trace
     ▼
  EVAL_RESULTS_DIR/<name>-<UTC time>/: run.json, questions.jsonl, summary.json
     │  (name: --name, or RETRIEVAL_MODE by default; RETRIEVAL_MODE-smoke with --smoke)
     ▼
  write_table (eval/table.py): ablation.md, one row per (name, golden_sha256)
```

`make eval-retrieval` (`python -m orgknow.eval retrieval`) runs the same label check, then retrieves in `RETRIEVAL_MODE` for every answerable question from its stored vector, scores the hits and prints the mode and the 4 metric means. No Voyage or Anthropic call (a missing vector is an error), and it writes nothing: the free check before a paid run.

## Components

| Path | What it does |
|---|---|
| `src/orgknow/settings.py` | `Settings` (pydantic-settings) reads `DATABASE_URL` (required, plain `postgresql://` form), `DB_CONNECT_TIMEOUT_S`, the corpus paths (`CORPUS_MANIFEST_PATH`, `CORPUS_LOCK_PATH`, `CORPUS_CACHE_DIR`), `INGEST_SCOPE` (default `full`), `CLAIM_SYNONYMS`, `CHUNK_MAX_TOKENS` (512), the embedding settings (`VOYAGE_API_KEY`, `VOYAGE_API_URL`, `EMBEDDING_MODEL`, batch and per-run token limits), the retrieval settings (`RETRIEVAL_TOP_K` 10, at most 40; `RETRIEVAL_MODE` `dense`, `hybrid` or `rerank`, default `hybrid` since S07-T4's eval; `RETRIEVAL_CANDIDATES` 20; `RRF_K` 60; `HNSW_EF_SEARCH` 100, which must be at least `RETRIEVAL_TOP_K` and `RETRIEVAL_CANDIDATES`; `RERANK_MODEL` `BAAI/bge-reranker-base`, `RERANK_REVISION` its pinned commit, `RERANK_MAX_LENGTH` 512 (1–512), `RERANK_BATCH_SIZE` 8 (1–256)), the generation settings (`GENERATION_MODEL` `claude-opus-5-5`, `GENERATION_EFFORT` `medium`, `GENERATION_MAX_TOKENS` 16,000, `ANTHROPIC_API_KEY`), the tracing settings (`LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_BASE_URL`) and the eval paths (`EVAL_GOLDEN_PATH`, `EVAL_RESULTS_DIR`, `EVAL_VECTORS_DIR`) from the environment, falling back to `.env`. Keys are `SecretStr`. It is built inside factories, never at import time. |
| `src/orgknow/api/app.py` | `create_app(settings=None)` builds the FastAPI app. `GET /health` is liveness: always 200, never touches the database. `GET /ready` is readiness: 200 if the database answers, otherwise 503. |
| `src/orgknow/db/health.py` | `is_reachable()` opens a fresh psycopg connection with a timeout and runs `SELECT 1`. |
| `src/orgknow/db/url.py` | `with_psycopg_driver()` rewrites `postgresql://` to `postgresql+psycopg://`, the form SQLAlchemy needs. Only Alembic uses it. |
| `src/orgknow/db/migrations/` | Alembic environment and hand-written migrations (raw SQL, no autogenerate, no offline mode). `0001` enables `vector`. `0002` enables `btree_gist` and creates the 6 domain tables with 28 named constraints. `0003` re-keys `embeddings` by `(content_hash, model)` and indexes `chunks.content_hash`; its downgrade recreates `0002`'s empty table (vectors are a cache). `0004` adds the HNSW index on `embeddings.embedding` (`vector_cosine_ops`, pgvector's default build settings). `0005` adds `chunks.search_vector`, a stored generated `tsvector` (`to_tsvector('english', text)`: stop words dropped, words stemmed), and its GIN index. |
| `src/orgknow/db/models.py` | Pydantic models at the data-access boundary (ADR-005): `Release`, `VersionData` / `NewVersion` / `Version` (timezone-aware datetimes only), `NewChunk` (no hash field), and the read results `VersionToChunk`, `TextToEmbed`, `Hit` (one retrieved chunk text: its cited chunk, distance (None when only lexical search found it), release windows, KEP claims and snapshot, and why it ranked there: its RRF score and its dense and lexical ranks), `Counts` and the fingerprint's `StoredDocument` / `StoredAlias` / `StoredVersion` / `StoredChunk` (every stored corpus value except generated ids). |
| `src/orgknow/db/releases.py` | `upsert_releases`: inserts new releases and updates the dates of existing ones; never deletes. `list_releases`: the stored releases, oldest first (ingest's read-only check). |
| `src/orgknow/db/documents.py` | `create_document`, `add_alias`, `resolve_document`. The two writes check the other table first (rule R3). |
| `src/orgknow/db/versions.py` | `insert_version`, `close_version` (only an open version, and never a release `until` that is set to another value, R10), `list_versions` (a document's versions, oldest first), and the two reads that hold the window conventions: `versions_at_release` (inclusive) and `version_at_time` (half-open). |
| `src/orgknow/db/chunks.py` | `versions_without_chunks`, `add_chunks` (computes each `content_hash` as SHA-256 of the text, R13), `texts_without_embedding` (distinct texts with no vector for a model: the embedding cache check), `add_embedding` (by `content_hash`; sends the vector as pgvector's text form) and `delete_orphan_embeddings` (vectors whose hash no chunk has). |
| `src/orgknow/ingestion/manifest.py` | `load_releases`: reads the manifest's release list and rejects it unless it is contiguous from `first` to `latest`, with ascending release dates and end of life after release. `load_scope` resolves a named scope (`scopes:` block) to snapshots at the locked SHAs: one release-scoped group per source type (docs pages, website release records, feature gates) from its `from_release`; the CHANGELOGs, one file per release, at the kubernetes lock head; the KEPs and governance docs at each release date plus `head`; and the blog, one log up to the website head. It refuses a scope where two groups would read one file. `load_normalization` reads the strip lists and refuses one that contains a `never_strip` key. |
| `src/orgknow/ingestion/git_reader.py` | Reads files, a commit's committer time, the merge time of a change (the last first-parent commit touching given paths), the blog's history (one first-parent log following renames) and git's similarity renames (`git diff -M50%` among given paths) from the partial clones with the `git` command. Returns the files it skips (symlinks, submodules, names without the group's suffixes) as records, which the report lists once per file and reason, and the manifest paths absent at every snapshot, which ingest reports as failures; a path absent at only some snapshots is logged. Fetches missing blobs on demand; a git failure raises `GitError` and stops the run. |
| `src/orgknow/ingestion/normalize.py` | Decodes (BOM, CRLF), splits front matter, and hashes the normalized text (ADR-002 D2): strip-listed front-matter keys removed, link targets dropped, whitespace collapsed. Front matter may open with 3 or more dashes. `docs_state` / `kep_state` (README + first YAML document of `kep.yaml`) / `single_kep_state` (an old single-file KEP) / `governance_state` (no front matter; the title only); `front_matter_time` reads a blog date as Hugo does. |
| `src/orgknow/ingestion/identity.py` | Canonical ids (ADR-002 D4): `web:` + docs path (`_index.md` / `index.md` → its folder), `gate:` + a gate's front-matter `title`, `kep:<n>` (an old single-file KEP: `kep:<sig>/<name>`), `community:` / `sig-release:` + a governance doc's first path, `web:` + a blog post's URL at publication, `changelog:1.R`, and alias ids from front-matter `aliases`. |
| `src/orgknow/ingestion/renames.py` | Pure functions that link each release's files to the next release's into chains, one per document: the redirect-file parser, the ordered link rules for web pages (same URL, redirect, `aliases`) and for gate files (same path, same title, `former_titles`), and for governance docs between date snapshots (same path), then git similarity ≥ 50% for what's left. Conflicts and links across source types are refused; unmatched adds and deletes are listed. |
| `src/orgknow/ingestion/history.py` | Pure functions from snapshots to versions: `release_history` (docs; a change at release R2 closes the previous version at R2 − 1, dates at release-day 00:00 UTC), `date_history` (KEPs, governance docs; a version starts at its merge time, and its release window never before 1.20) and `changelog_version` (`[R, R]` from the lock head's commit time). `plan_changes` compares derived and stored versions: insert all, nothing, close + insert, or a `HistoryMismatch`. |
| `src/orgknow/ingestion/chunker.py` | A 6-rule line scanner (headings outside fences, indented fences, Hugo `highlight` blocks, HTML tables kept whole, HTML comment blocks that make no text), sections by heading, packing by whole blocks up to `CHUNK_MAX_TOKENS` (chars ÷ 4), and the fixed chunk header (source, title, document id, heading path). A block over the limit stays whole, except a list, cut between its top-level items, and a pipe table, cut between its rows with each later piece starting with the header and delimiter rows; code blocks and HTML tables are never cut. A heading's text loses inline HTML comments and a trailing `{#id}` anchor. A gate's body starts with its `stages` (and `removed`) as YAML. A governance doc's title is its first `# ` heading. No source keeps a section under a `Downloads for …` heading; a CHANGELOG's chunks also leave out the text before the first heading. Pure functions. |
| `src/orgknow/ingestion/ingest.py` | `make ingest`: first checks, read-only, that the `releases` table holds every manifest release with the same dates (`list_releases`), and stops with "run `make seed`" before any git read if not; then runs one collector per source: the release-scoped groups at every release (pages and gate files linked into chains separately, each with its own rules and ids), the CHANGELOGs at the kubernetes lock head, the KEPs (grouped by number) and governance docs (chained) at each release date plus `head`, and the blog's history. It derives one document per chain, KEP, post or CHANGELOG (refusing two with one id), stores new versions and aliases with one transaction per document, then chunks every version that has none. Ends with the ingestion report (`ingestion/report.py`): this run's new rows, each skipped file once with the snapshots it was skipped at, each failure (after its snapshot's label where it failed at one), then the database part. A mismatch, an unparseable document or a manifest path absent at every snapshot makes the exit code non-zero while other documents still ingest. |
| `src/orgknow/ingestion/blog.py` | A blog post's URL (the manifest's permalink, Hugo's date and slug fallbacks), its publication moment (the first time Hugo renders it) and its stored versions: the one live at publication, then each later change; versions never public aren't stored. Pure functions. |
| `src/orgknow/ingestion/report.py` | The ingestion report's pure parts: `fingerprint` (the sha256 of one sorted JSON row per stored document, alias, version and chunk, every value except generated ids), `skip_lines` (one line per file and reason, its snapshots as release ranges) and the database part's layout (counts per source type and per release, aliases, the chunk id range, the fingerprint). `make ingest-report` (`main`) prints the database part alone, without reading git. |
| `src/orgknow/db/report.py` | The report's reads: counts per source type (one `GROUPING SETS` query) and per release, the chunk id range, and every stored document, alias, version and chunk for the fingerprint. Read-only. |
| `src/orgknow/embeddings/embedder.py` | The `Embedder` protocol (`model`, `embed(texts, input_type)`), reused for query embeddings in S04-R2. |
| `src/orgknow/embeddings/voyage.py` | `VoyageEmbedder`: one POST per batch with `urllib` (no SDK), 1024 dimensions, retries on 429/5xx only; pure `request_body` and `parse_response` (reorders by `index`, refuses wrong lengths). |
| `src/orgknow/embeddings/embed.py` | `make embed`: lists texts with no vector, refuses to start above `EMBED_MAX_TOKENS_PER_RUN`, deletes orphan vectors, then sends batches of at most 128 texts and 60,000 estimated tokens (one transaction per batch). |
| `src/orgknow/ingestion/seed.py` | `make seed`: validates the release list, then upserts it in one transaction. |
| `src/orgknow/db/retrieval.py` | `search`: one fixed query. The `k` texts nearest a question vector among one model's vectors (index-ordered by cosine distance, so HNSW is used; vectors no chunk uses are skipped), then each text expanded to the chunks holding it: the chunk in the newest version is cited, and every version's release window is listed, never merged. Ties are ordered by `content_hash`; `dense_rank` is the position. It first sets the HNSW search width with `set_config('hnsw.ef_search', …, true)` inside its own transaction block, so the width applies to its query even on an autocommit connection. `search_lexical`: the `n` texts holding every content word of the question (`plainto_tsquery('english', …)`, matched with `@@` through the GIN index), ranked by `ts_rank_cd` (closer words rank higher), one rank per text, then the same expansion; `distance` is None and `lexical_rank` is the position. |
| `src/orgknow/retrieval/fusion.py` | `rrf`: ranked id lists in, (id, score) out, score Σ 1/(k + rank), ties by id. `fuse`: the dense and lexical hits in, the top K fused hits out; a text in both lists keeps the dense hit's fields and gets both ranks. Pure. |
| `src/orgknow/retrieval/retrieve.py` | `retrieve`: embeds the question with `input_type="query"`, then by `RETRIEVAL_MODE`: `dense` calls `search` with `RETRIEVAL_TOP_K`; `hybrid` calls `search` and `search_lexical` with `RETRIEVAL_CANDIDATES` each, then `fuse` with `RRF_K` and `RETRIEVAL_TOP_K`; `rerank` fuses the same lists with no top-K cut, scores the whole pool with the `reranker` argument (ValueError without one; no call for an empty pool), then `rerank` keeps `RETRIEVAL_TOP_K`. `ask` and the eval call it. |
| `src/orgknow/retrieval/rerank.py` | The `Reranker` protocol (`score(question, texts)`: one score per text, in order) and `rerank`: the hits in fused order and their scores in, the top K out, sorted by the score rounded to 4 decimals, ties keeping fused order; each hit keeps hybrid's fields and gets the raw score as `rerank_score`. A score count unlike the hit count raises ValueError. Pure. |
| `src/orgknow/retrieval/cross_encoder.py` | `CrossEncoderReranker`: `AutoTokenizer` + `AutoModelForSequenceClassification` at `RERANK_MODEL`@`RERANK_REVISION` (safetensors only), on CPU with torch's default thread count. `score` reads texts shortest first in batches of `RERANK_BATCH_SIZE`, each (question, text) pair cut to `RERANK_MAX_LENGTH` tokens, under `torch.inference_mode()`; the score is the pair's logit, returned in the caller's order. The only module importing `torch` and `transformers`; imported only in rerank mode. A model missing from the Hugging Face cache downloads once; offline, loading raises OSError. |
| `src/orgknow/retrieval/dense.py` | A demo: `main()` embeds a question and prints the `RETRIEVAL_TOP_K` nearest hits from `search`, whatever `RETRIEVAL_MODE` says. |
| `src/orgknow/generation/schema.py` | The answer models: `ModelAnswer` (what the model returns: status, answer, cited chunk ids, reason), `Evidence` (one filled-in citation), `Answer` (what `ask` prints) and `AnswerTrace` (what the trace records about the model call; never printed). |
| `src/orgknow/generation/prompt.py` | The fixed system prompt and the user message: one evidence block per hit (chunk id, release windows, a KEP's claimed status and stage, the chunk text), then the question. Pure functions. |
| `src/orgknow/generation/generator.py` | `answer`: prompt, one model call, validate, fill in. No hits: `insufficient_evidence` without a call. `AnthropicGenerator` calls `messages.parse` with the answer schema and the effort setting, behind the `Generator` protocol. A refusal, a cut-off or output off the schema raises `GenerationError` with the stop reason. |
| `src/orgknow/generation/validate.py` | The citation validator: an answer citing an id that wasn't retrieved, an `answered` with no citations or an `insufficient_evidence` with no reason becomes `insufficient_evidence` with reason `citation_validation_failed: [...]`. `fill_in` builds each citation from its hit, with a GitHub URL at the snapshot commit. Pure functions. |
| `src/orgknow/cli.py` | `orgknow ask "<question>"` (argparse; the `orgknow` console script). `main` checks the keys, loads the reranker in rerank mode (`load_reranker`, which imports `cross_encoder` only then; a failed load prints one line and exits 1) and builds the real Voyage, Anthropic and Langfuse clients; `ask` retrieves, answers and prints the JSON. Without both Langfuse keys it prints "tracing off" and builds no Langfuse client. Expected failures (a `GenerationError`, the Anthropic SDK's API errors, the Voyage client's errors) print one stderr line and exit 1; an empty question exits 2. The only caller of Langfuse: the trace holds the question, `retrieve` (mode, k, model; per hit the chunk id, distance, RRF score, dense and lexical ranks and rerank score), `generate` (model, effort, prompt, output, token usage, stop reason), `validate` (result, rejected ids) and the final JSON, and never the settings or a key. |
| `src/orgknow/eval/golden.py` | The golden-set file (ADR-007): `load_golden_file` validates it (unknown keys, types, the release window, the rules across fields, nested or duplicate labels), each error naming the question id and field. `check_labels` resolves each label's document (alias → canonical_id) and counts the distinct texts it matches; `section_matches` is the one label rule, heading by heading. `list_sections` for `make eval-sections`. |
| `src/orgknow/db/eval.py` | The label check's reads: `canonical_ids` (a name or alias → its canonical_id) and `document_texts` (a document's distinct (heading path, text) pairs in order of first appearance). Read-only. |
| `src/orgknow/eval/metrics.py` | `score_retrieval`: Recall@K, Hit@K, MRR, nDCG@K and distinct sections for one question's hits; each label is credited once, at its first matching hit (ADR-007 D3). Pure. |
| `src/orgknow/eval/checks.py` | `check_answer`: AC1 (an `answered` answer has citations, each with a URL, windows and source type), AC2 (every cited chunk was retrieved), AC3 (an unanswerable question got `insufficient_evidence` with a reason) and the false-refusal flag; each true, false or n/a. Pure. |
| `src/orgknow/eval/runner.py` | `run`: the label check, then one Voyage request for the questions with no stored vector (saved to the vector file), then per question `retrieve` (through `StoredVectors`, an `Embedder` over the file), `answer`, the metrics and checks; writes `run.json`, `questions.jsonl` and `summary.json`. An ask error (`cli.ASK_ERRORS`) is a row with `answer: null` and its error. Each hit row records its distance, RRF score, ranks and rerank score, and `run.json` records the 4 retrieval settings (null in folders written before S07) and, in rerank mode, the model, revision, max length, batch size, torch's thread count and the model's load time (null otherwise and in older folders). In rerank mode, `run` and `score_retrieval_only` get the reranker their caller loaded once. `check_golden` is the label check `run` shares with `score_retrieval_only` (`make eval-retrieval`: retrieval from stored vectors only, scored; `retrieval_report` prints it). |
| `src/orgknow/eval/table.py` | `write_table`: rebuilds `ablation.md` from every folder with a `summary.json`: one row per pipeline name and golden file hash, each value the mean over runs with its range. |
| `src/orgknow/eval/__main__.py` | `python -m orgknow.eval check \| sections \| run \| retrieval \| table` (the `eval-*` Make targets). `run` needs `ANTHROPIC_API_KEY`, and `VOYAGE_API_KEY` only when a vector is missing; its `--name` defaults to `RETRIEVAL_MODE` (`<mode>-smoke` with `--smoke`, so smoke runs get their own table row). `retrieval` needs no key. In rerank mode, both load the reranker once, before the question loop, and time the load. Errors print one stderr line and exit 1. |

Every data-access function takes a `psycopg.Connection` and leaves the transaction to the caller (ADR-005). `src/orgknow/db/` is the only place with SQL, and every query is a fixed string with parameters.

There is no server entry point yet (no ASGI server dependency). The app runs only inside tests, through FastAPI's `TestClient`. The command-line entry point is the `orgknow` console script (`[project.scripts]` in `pyproject.toml`).

## Database

`compose.yaml` runs one service: the pinned `pgvector/pgvector:0.8.1-pg18` image (ADR-004), published on `127.0.0.1:5433`. Data lives in the named volume `pgdata`, so it survives `make down`. A `pg_isready` healthcheck over TCP lets `make up` block until the database accepts connections.

The schema is specified in `docs/domain-model.md`:

| Table | Holds | Key rules |
|---|---|---|
| `releases` | One row per minor release (key `minor`, 24 = v1.24), seeded from the manifest | version matches minor; end of life after release |
| `documents` | One stable identity per document (`canonical_id`, `source_type`) | unique id with a known prefix; known source type |
| `document_aliases` | Old URLs and gate names pointing at a document | unique; never equal to a `canonical_id` (code check) |
| `document_versions` | One row per content change, with a release window and a date window | date windows of one document never overlap (`EXCLUDE … tstzrange … WITH &&`), so at most one is open |
| `chunks` | The embedded text of each version, by position, and its `search_vector` (generated by the database) | unique position per version; deleted with their version |
| `embeddings` | One `vector(1024)` per distinct chunk text per model (key `(content_hash, model)`); the table is the embedding cache | exactly 1024 numbers; well-formed hash; vectors no chunk uses are deleted by `make embed` |

`embeddings.embedding` has an HNSW index for cosine distance (`0004`). On 20 real queries it returned the same top 10 as an exact scan (200 of 200); at the search width 100, 20 candidates matched an exact scan on all 43 golden questions (S07-R1). `chunks.search_vector` has a GIN index for full-text matches (`0005`).

After `make seed`, `make ingest` and `make embed` on the S04 scope, the dev database held 44 documents (43 docs pages, KEP-2579), 220 versions, 4,967 chunks with 1,583 distinct texts, and 1,583 `voyage-4-large` vectors. After `make reset-corpus && make ingest` on the `full` scope (S05-R1), it held 564 documents (64 docs pages, 8 release records, 491 feature-gate documents, KEP-2579), 1,332 versions, 9 aliases and 10,509 chunks. After S05-R2 it held 1,168 documents (64 docs pages, 26 release records of which 18 are CHANGELOGs, 491 feature-gate documents, 141 KEPs, 29 governance docs, 417 blog posts), 2,882 versions, 21 aliases and 48,194 chunks (20,499 distinct texts). After S05-R3's chunker changes it holds the same documents, versions and aliases, and 48,273 chunks with 21,552 distinct texts, each with one `voyage-4-large` vector (21,552 vectors). A from-empty ingest takes about 1.5 minutes; the full embed took 3 min 44 s.

`tests/integration/conftest.py` marks every test in that directory `integration`, so `make check` excludes them and `make test-int` selects only them. Integration tests connect only to `TEST_DATABASE_URL` (the `orgknow_test` database that `make up` creates), so data ingested into the dev database never collides with test rows. The `conn` fixture rolls back every test's writes, and `seeded_releases` loads the 18 releases inside that transaction, so tests work on an empty or a seeded database. `tests/conftest.py` holds the `make_git_repo` fixture (a tiny git repo with controlled committer dates), the fake embedder and the fake generator. No test calls Voyage, Anthropic or Langfuse. `tests/fixtures/` holds small real corpus files, pinned.

## Verification loop

| Where | What runs |
|---|---|
| Every commit | pre-commit: `ruff check --fix` and `ruff format` |
| `make check` | ruff format check, ruff lint, `mypy --strict` on `src/`, unit tests |
| `make test-int` | migrates the test database, then runs the integration tests against it |
| CI (`.github/workflows/ci.yml`) | `check` job: `make check`. `integration` job: the same pgvector image as a service container, `make migrate` twice (the second run must be a no-op), a round trip down to `0001` and back up, then `make test-int` with `TEST_DATABASE_URL` set to the service database. |

CI calls the same Make targets as local development, and `UV_LOCKED=1` makes it fail if `uv.lock` is out of date. CI never runs `make seed`: tests seed what they need inside their own transaction.
